Проверено 02.10.2026 локально на Windows, Python 3.13.5, в отдельной `.venv`.

| Проверка | Результат |
|---|---|
| `ruff check .` и `ruff format --check .` | Успешно |
| `pytest -q` | 83 теста проходят |
| `scripts/check_imports.py` | Импортированы все 17 модулей пакета |
| `python -m app.main --smoke` | Два scan, snapshots, измеренный рост, TOP-3, mock MP4 delivery, очистка |
| `bash -n install.sh` | Синтаксис корректен |

Тесты охватывают фильтры, рост, ranking, доставку и дедупликацию, паузу/остановку, авторизацию, динамические запросы, SQLite, расписание и retention. Для автоматического поиска проверены ожидание реального ответа после служебного JSON, нормальная инициализация браузерной сессии, остановка при CAPTCHA, повтор на следующем цикле, продолжение после ошибки отдельного запроса, поиск хэштегов через обычную поисковую страницу и доступная пустая выдача. Старые результаты не вытесняют свежие из лимита кандидатов. Сообщения об отказе поиска отличаются от отсутствия подходящих видео.

## Команда ручного скана

Для `/scan` дополнительно проверены авторизация и глобальная остановка, запуск на личной паузе, отчёт после поиска, общий cooldown, перенос следующего автоматического цикла, отсутствие пересечения ручного и автоматического сканов, ответ на `/status` во время работы, ошибки provider и общий timeout, отмена задачи и освобождение locks при остановке polling. Команда зарегистрирована в меню Telegram и справке. Эти проверки выполнены с fake provider и fake Telegram; реальный запуск команды на VPS проверяется после обновления.

## Реальный автоматический поиск

Ручные ссылки не использовались. Ни токен Telegram, ни TikTok-аккаунт для проверки не требовались.

- Повторная live-проверка 0.1.4: `нарезка из фильма`, limit=100 — 12 настоящих видео, 1 порция, 0 свежих; `stop_reason=login_required`. Диалог входа не закрывался. Это подтверждает внешний предел анонимной выдачи, а не получение 100 результатов на реальном TikTok.
- Переход на обычную вкладку «Видео» вернул страницу ошибки сервера. Доступный серверный фильтр даты не обнаружен; он не заявляется реализованным.
- Бесплатный сторонний API TikWM вернул HTTP 403 с проверкой доступа. В программу не подключён.
- Пагинация проверена на моделируемой браузерной выдаче: свежие видео после старой первой страницы доходят до SQLite/ranking; работают wheel и видимая кнопка, лимиты страниц/видео, ответы data/item_list, дедупликация, остановка без прогресса, вход и CAPTCHA, сохранение первой порции при timeout. Проверено сохранение кандидатов перед пропуском новых запросов из-за бюджета scan.
- Загрузка собственной сессии в контекст и атомарный экспорт файла проверены без настоящего аккаунта. Реальная авторизованная пагинация, доступность фильтров после входа и принятие сессии на VPS не проверены: пользовательский аккаунт не подключён.

Результаты более ранних проверок этой же даты:

- Поиск `нарезка из фильма` нашёл видео `7691731925597293831` с реальной датой публикации, возрастом 19,47 часа и 21 100 просмотрами. `eligible_count=1` по настроенным фильтрам возраста, просмотров, тематики и языка. Наличие русского языка оценивается эвристикой по описанию, хэштегам и доступным субтитрам, а не проверкой аудио.
- Запрос `#фильм` через `/search?q=…` вернул настоящие metadata. Проверенные результаты старше 24 часов и в подборку не входят.
- При последовательной проверке десяти запросов получены 104 уникальных видео; один прошёл фильтры. Последующий переход на страницу `/tag/…` потребовал CAPTCHA. Такие страницы удалены из рабочего поиска: хэштеги передаются в обычный поисковый запрос.
- Попытка получить дополнительные результаты через вкладку «Видео» и публичные профили не дала подтверждённого источника свежих публикаций; встречалась CAPTCHA. Эти варианты в программу не добавлены, проверки не обходились.

Ранее публичные metadata диагностического видео `7288826284572937515` и MP4 размером 2 404 292 байта были проверены через обычные страницы/CDN. Старое видео не добавлялось в рабочую подборку.

## Практические ограничения

Первичная выдача подтверждена на реальных данных. Анонимный поиск в повторной проверке требовал вход для продолжения, поэтому исправление алгоритма и лимит 100 сами по себе не гарантируют больше результатов на VPS. Бот теперь показывает конкретную глубину и причину остановки; можно подключить собственную сессию после ручного входа. Сессия не гарантирует отсутствие дополнительной проверки на сервере. При CAPTCHA бот останавливается и сам повторяет поиск на следующем цикле; ручного резерва нет. Получение трёх подходящих свежих роликов на каждом цикле не заявляется проверенным.

Доступ к VPS отсутствует. Реальная отправка Telegram и apt/systemd локально не выполнялись; проверены mocked Bot API, команды, offline smoke и синтаксис установщика. Пользователь сообщил об успешной авторизации и запуске сервиса на VPS. GitHub Actions настроен на Python 3.12/Ubuntu 24.04; результат удалённого CI в этой сессии не проверен. OCR и необязательный TMDB покрыты локальными тестами; live TMDB key не предоставлен.
