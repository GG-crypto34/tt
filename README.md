# Movie Trend Bot

Telegram-бот для небольшой группы: мониторит свежие русскоязычные TikTok-нарезки из фильмов и сериалов, измеряет прирост счётчиков и отправляет TOP-3 каждые три часа по Москве. MP4 скачиваются только для выбранной подборки. Общий пароль открывает обычные команды; отдельный пароль управляет глобальным поиском и рассылкой.

**Версия 0.1.1:** исправлена загрузка поиска: новая обычная браузерная сессия сначала открывает главную страницу, затем ожидает настоящие ответы поиска до SEARCH_WAIT_SECONDS (12 секунд по умолчанию). Поиск по словам проверен на реальных TikTok-результатах без входа в аккаунт. Анонимная выдача ограничена, может содержать преимущественно старые ролики; поиск хэштегов на проверенном подключении остаётся недоступен. Ноль подходящих кандидатов возможен и при работающем поиске из-за фильтров ≤24 часов и ≥10 000 просмотров. Публичные ссылки в `data/seed_urls.txt` остаются необязательным резервом. Обхода CAPTCHA, логина, подписывания закрытых API и платного scraper нет.

## Установка на Ubuntu 24.04

Нужен обычный пользователь с sudo, 2 CPU, 2 GB RAM, около 50 GB диска и исходящий HTTPS. Python 3.12 входит в Ubuntu 24.04. В репозитории пока нет remote; замените `URL_РЕПОЗИТОРИЯ` на адрес своего опубликованного репозитория.

```bash
sudo apt-get update
sudo apt-get install -y git
git clone URL_РЕПОЗИТОРИЯ movie-trend-bot
cd movie-trend-bot
chmod +x install.sh
./install.sh
nano .env
```

Установщик проверяет Ubuntu 24.04, устанавливает Python/venv, FFmpeg, Tesseract с русским и английским языками, зависимости Playwright и Chromium Headless Shell. Создаёт локальную `.venv`, каталоги `data`, `media`, `logs`, `.env` из примера **только при его отсутствии** и systemd unit с вашим пользователем и абсолютным путём. Повторный запуск сохраняет `.env` и БД. Приложение не запускается от root. Установка требует сети; сервис не включается до настройки.

Не копируйте `.env.example` поверх настроенного файла. Обязательно заполните:

```dotenv
TELEGRAM_BOT_TOKEN=токен_от_BotFather
USER_PASSWORD=длинный_общий_пароль
ADMIN_PASSWORD=другой_длинный_пароль
```

В официальном [@BotFather](https://t.me/BotFather) выполните `/newbot`, задайте имя и username, сохраните выданный токен в `.env`. При утечке перевыпустите токен. Пароли должны различаться. Секреты не помещайте в Git.

```bash
.venv/bin/python -m app.main --check-config
.venv/bin/python -m app.main --smoke
sudo systemctl enable --now movie-trend-bot
sudo systemctl status movie-trend-bot
journalctl -u movie-trend-bot -f
```

В личном чате отправьте `/start`, затем общий пароль отдельным сообщением. На ввод есть две минуты. Авторизация сохраняется после restart. Групповые сообщения не обрабатываются. Пароль удаляется из чата по возможности и никогда не записывается в БД/лог.

Ручной запуск вместо systemd:

```bash
export PLAYWRIGHT_BROWSERS_PATH="$PWD/.tools/ms-playwright"
export OMP_THREAD_LIMIT=1
.venv/bin/python -m app.main
```

Перед ручным запуском остановите systemd. ОС-блокировка `data/process.lock` запрещает второй экземпляр с той же БД. Используется long polling; webhook не устанавливается. Если токен раньше использовался с webhook, удалите его через Telegram Bot API перед запуском.

## Резервный мониторинг ссылок

Добавьте в `data/seed_urls.txt` полные публичные ссылки, по одной на строку:

```text
# Комментарии начинаются с #.
https://www.tiktok.com/@имя_автора/video/числовой_ID
```

Это пример формата: вставьте настоящие ссылки. Короткие `vm.tiktok.com` ссылки сначала откройте вручную и скопируйте полный URL. Имена фильмов добавлять не нужно. Файл перечитывается на следующем scan. При недоступности поиска можно установить `BROWSER_ENABLED=false`: metadata читаются напрямую из HTML. Если и HTML недоступен, бот сообщает об ошибке и продолжает отвечать.

Все фильтры применяются и к резервным ссылкам: возраст ≤24 часов, просмотры ≥MIN_VIEWS, кинотематика и русский язык. Старое известное видео подходит для диагностики, но не для подборки.

Проверка provider без Telegram-секретов:

```bash
export PLAYWRIGHT_BROWSERS_PATH="$PWD/.tools/ms-playwright"
.venv/bin/python scripts/probe_provider.py --query фильм
.venv/bin/python scripts/probe_provider.py --query '#фильм'
.venv/bin/python scripts/probe_provider.py --url 'ПОЛНЫЙ_TIKTOK_URL'
.venv/bin/python scripts/probe_provider.py --url 'ПОЛНЫЙ_TIKTOK_URL' --download
```

Последняя команда проверяет один MP4 во временном каталоге и сразу удаляет его; отправки в Telegram нет. Недоступность provider возвращает ненулевой exit code.

## Telegram-команды и пароли

| Команда | Действие |
|---|---|
| `/start` | Общий пароль и авторизация |
| `/status` | Авторизация, глобальное состояние, личная пауза, последний scan, новые актуальные кандидаты, следующая рассылка и здоровье provider |
| `/top` | Текущие TOP-3 для вас, не чаще раза в минуту |
| `/pause` | Приостановить только вашу автоматическую рассылку |
| `/resume` | Включить вашу автоматическую рассылку |
| `/queries` | Базовые и одобренные временные запросы |
| `/logout` | Удалить авторизацию; история доставок сохраняется |
| `/about` | Описание и источники данных |
| `/stop_service` | ADMIN_PASSWORD и глобальная остановка scan/доставки |
| `/start_service` | ADMIN_PASSWORD и возобновление scan/доставки |

Все авторизованные пользователи имеют одинаковые обычные права. Отдельных ролей нет. Для глобального управления сначала требуется обычная авторизация, затем ADMIN_PASSWORD. Пароль вводится следующим сообщением; `/stop_service password` не принимается. После пяти неверных попыток ввод блокируется на 15 минут; счётчик хранится в SQLite.

Глобальная остановка сохраняется после restart. Команды и очистка продолжают работать. Уже начатый внешний запрос завершится в пределах timeout; новые запросы и отправки прекратятся на ближайшей проверке состояния. Личная пауза также проверяется перед каждой автоматической отправкой; `/top` работает на личной паузе. Заблокировавшему бота пользователю рассылка приостанавливается.

## Provider: выбор и ограничения

Один асинхронный Python-процесс, SQLite WAL, обычный публичный Playwright provider, отдельные Protocol-интерфейсы источников и распознавания, Telegram Bot API через HTTPX. Без платных API и постоянно загруженных ML-моделей.

`PublicTikTokProvider` читает HTML/hydration JSON публичного видео. Новая сессия сначала посещает публичную главную страницу, затем открывает обычные `/search?q=…` и `/tag/…` одним Chromium. Provider ожидает ответы страницы, пропускает пустые/служебные ответы и читает настоящий search JSON; прежнего фиксированного ожидания 2,5 секунды нет. Медиа, изображения и шрифты при поиске не загружаются. Закрытые endpoints вручную не вызываются. CAPTCHA не решается. При пустых данных прекращаются повторные запросы того же вида до следующего scan. Chromium закрывается после scan. Если запросы работают, а хэштеги нет, `/status` показывает частичную доступность.

TikTok может требовать вход, ограничивать регионы, менять JSON или отдавать пустые результаты. Поиск не гарантирует сортировку по дате и полноту. Число подписчиков иногда неизвестно. Недоступное видео не создаёт ложных snapshots; счётчики старше двух интервалов scan исключаются из доставки.

Исследование первичных источников:

- [TikTok Display API](https://developers.tiktok.com/docs/en/tiktok-api-v2-video-list) получает видео разрешившего доступ пользователя и не заменяет общий поиск.
- [TikTok Research API](https://developers.tiktok.com/docs/en/research-api-get-started) предусматривает специальное получение доступа, поэтому не выбран для личного бота.
- [Playwright: сетевые ответы](https://playwright.dev/python/docs/network) позволяет читать данные обычной публичной страницы.
- [Исходный extractor yt-dlp](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/tiktok.py) использован для проверки публичных полей и субтитров. yt-dlp не является зависимостью: MP4 скачивается с публичного TikTok CDN без дополнительного anti-bot кода.
- [Telegram Bot API](https://core.telegram.org/bots/api#sendvideo): проект ограничивает MP4 49 MB при текущем лимите API 50 MB.

Live-проверка 02.10.2026 в локальной Windows-среде: после исправления инициализации/ожидания запрос `фильм` получил 12 реальных результатов, `момент из фильма` — 11. Во второй выдаче самый свежий ролик имел возраст около 28 часов и не прошёл жёсткий фильтр; более старые ролики также исключены. Хэштег `#фильм` не отдал metadata/search JSON. Ранее видео `7288826284572937515` вернуло настоящие metadata, дату, 42 300 000 просмотров и CDN URL, MP4 размером 2 404 292 байта скачан и удалён. Это старое диагностическое видео: оно не добавляется в рабочие запросы. Доступность конкретного VPS проверяется отдельно.

## Ranking и расписание

Scan запускается сразу, затем раз в 15 минут от начала предыдущей попытки. Два scan не перекрываются. Общий бюджет scan — SCAN_TIMEOUT_SECONDS=600 секунд: недоступные seed URLs не могут удерживать очередь бесконечно. Поиск, refresh и подготовка подборки используют общий lock; Telegram polling работает независимо. Число отслеживаемых видео ограничено 200, поиск — 15 результатов на запрос, обращения последовательные.

Timestamp snapshot соответствует получению данных. Скорость — разница последнего snapshot и ближайшего более раннего независимого snapshot, разделённая на часы. Интервалы <60 секунд пропускаются; отрицательный прирост становится нулём. Первый замер использует `views / max(age_hours,0.25)` и confidence 0.55, следующий независимый — confidence 1.0.

Trend Score 0–100:

| Компонент | Вес | Нормализация |
|---|---:|---|
| Просмотры/час | 40% | log1p, clipping при 100 000/ч, confidence |
| Лайки/час | 20% | log1p, clipping при 10 000/ч, confidence |
| Доля репостов | 15% | clipping при 3% |
| Доля комментариев | 10% | clipping при 1% |
| Свежесть | 10% | от 1 до 0 за 24 часа |
| Breakout | 5% | log1p(views / max(followers,100)); неизвестная аудитория даёт 0.5 |

Engagement немного корректирует скорости. Веса нормализуются суммой. Выбросы ограничены и не меняют шкалу других видео. Формула подробно комментирована в `app/ranking.py`. Это стартовая эвристика, не прогноз просмотров.

Языковая релевантность комбинирует долю кириллицы в caption, русские хэштеги и доступные русские субтитры. Возвращает evidence score, не вероятность, и не требует всех признаков. OCR/скачивание для каждого кандидата не выполняются. Релевантные видео ниже MIN_VIEWS тоже отслеживаются: они могут пересечь порог позднее.

Рассылка привязана к `Europe/Moscow`: 00:00, 03:00, 06:00, 09:00, 12:00, 15:00, 18:00, 21:00. Restart не сдвигает часы. Пропущенные циклы не догоняются (одна минута допуска). Перед запуском слот атомарно записывается в SQLite, поэтому restart не повторяет цикл.

Общая подборка содержит до трёх лучших подходящих роликов, ещё не доставленных хотя бы одному получателю. Каждый получает только не виденные ролики этой подборки. Если вы видели часть через `/top`, ваша автоматическая подборка может быть короче трёх; остальные получают общий TOP полностью. Слабые подходящие кандидаты заполняют оставшиеся места; при пустой подборке отправляется сообщение об отсутствии видео.

## Доставка и повторы

Уникальность `deliveries(user_id,video_id)` защищает каждого отдельно. `/top` не помечает доставку другим. Один MP4 кратковременно используется для всех получателей.

Перед отправкой создаётся pending reservation, после успешного ответа — sent с message ID. При явном отказе Telegram reservation удаляется. При неоднозначном исходе (timeout после upload) сохраняется: приоритет — отсутствие повторов, поэтому в редком случае сообщение может быть пропущено. Bot API не предоставляет idempotency key для sendVideo; одновременно гарантировать отсутствие дублей и доставку после любого сбоя нельзя.

Read-запросы повторяются до трёх раз с backoff, 429 учитывает Retry-After. Telegram send повторяется только после явного 429. Недоступный/слишком большой MP4 заменяется ссылкой и статистикой. Caption длиннее 1024 символов дополняется отдельным текстовым сообщением. Ошибка source identification не отменяет доставку.

## Определение фильма/сериала

Каскад `SourceIdentifier`: явное название в caption → публичные субтитры TOP → OCR трёх кадров на 2/8/16 секунде → необязательная проверка точного названия в TMDB. FFmpeg ограничен одним потоком, OCR последователен, общий timeout 90 секунд. Кадры удаляются сразу, результат кэшируется в БД.

Извлекаются конструкции `Фильм «Название»` и `Название фильма: Название`. Случайный хэштег не считается доказательством. Confidence — эвристическая сила доказательств. TMDB подтверждает существование названия, а не принадлежность сцены. Неуверенный результат помечается «Возможно», отсутствие доказательств — «Источник: не удалось определить».

ASR/Whisper и общий веб-поиск по репликам в этой версии не подключены: выбран ограниченный каскад metadata/subtitles/Tesseract для 2 GB RAM. Распознавание кадра без явного названия обычно останется неизвестным. Фиктивных результатов и обязательной ML-модели нет.

## Бесплатные сервисы и TMDB

Обязательны Telegram Bot API и доступные публичные TikTok-страницы/CDN. Playwright, FFmpeg, Tesseract работают локально. Кредитных карт и автоматического перехода на платный тариф нет.

TMDB_API_KEY необязателен. По [официальному FAQ](https://developer.themoviedb.org/docs/faq), API бесплатен для некоммерческого использования с атрибуцией. Developer key получается в настройках аккаунта TMDB. Без ключа остаются caption, субтитры и OCR. При rate limit/ошибке ключа/недоступности каталога исходный результат сохраняется, платного fallback нет.

Атрибуция: [The Movie Database](https://www.themoviedb.org), [официальные логотипы и правила](https://www.themoviedb.org/about/logos-attribution). This product uses the TMDB API but is not endorsed or certified by TMDB. `/about` и captions показывают источник при включённой интеграции.

## Временные запросы и review

Хэштег предлагается после появления на QUERY_THRESHOLD разных подходящих видео за сутки. Базовые запросы не предлагаются. Всем авторизованным пользователям, включая личную паузу, приходят inline-кнопки. Первый conditional UPDATE решает исход. Повторное нажатие сообщает о принятом решении. Сообщения обновляются; неотредактированные кнопки тоже не могут изменить исход.

Одобренный запрос живёт 24 часа. Если он возвращает подходящие видео именно с этим хэштегом, TTL продлевается от последнего успеха. Посторонние fallback-ссылки TTL не продлевают. Отклонённые/истёкшие запросы имеют cooldown 7 дней. Повторное предложение получает новый ID: старые кнопки не могут решить новую заявку. Pending-предложения истекают через сутки.

## Хранение и очистка

SQLite `data/bot.sqlite3` автоматически инициализирует schema v1, WAL и индексы. Таблицы: users, videos (metadata и кэш source), metric_snapshots, deliveries, dynamic_queries, review messages, hashtag evidence, auth attempts, service state, broadcast slots. Для резервной копии остановите сервис и сохраните весь каталог data.

Очистка при старте и каждую минуту, даже при глобальной остановке: snapshots >48 часов, videos >48 часов, deliveries >30 дней, истёкшие queries/cooldown, старые слоты/auth attempts. MP4 удаляется около шестичасового TTL с минутным запасом; `.part`/`.tmp` и orphan OCR-каталоги — через 30 минут. Активные файлы защищены до окончания операции. После выключенного сервера очистка происходит при следующем старте. Авторизация, личная пауза, global_enabled не очищаются.

Очистка не следует symlink, не выходит за media, удаляет только известные типы временных файлов. Локальный TTL не удаляет видео/сообщения из Telegram.

## Логи и troubleshooting

JSON-логи идут в stdout/journal и `logs/bot.log`, три резервных файла по 2 MB. Содержат scan/queries, фильтры, ranking, delivery, cleanup, source и глобальное управление. Formatter скрывает пароли, токен и TMDB key; тексты входящих сообщений не логируются.

| Симптом | Проверка |
|---|---|
| Не запускается | --check-config, затем journalctl -u movie-trend-bot -n 100 |
| Telegram 401 | Проверьте/перевыпустите токен |
| Telegram 409 | Другой poller или оставшийся webhook |
| Нет кандидатов | Provider health в /status; свежесть seed URLs, MIN_VIEWS, язык/тема |
| Поиск недоступен | probe_provider.py; seed fallback без обхода CAPTCHA |
| Chromium не найден | PLAYWRIGHT_BROWSERS_PATH, повторите install.sh |
| MP4 заменён ссылкой | CDN, timeout, размер >49 MB или отказ Telegram |
| Источник неизвестен | Нет явного названия; tesseract --list-langs; это допустимый результат |
| После restart нет рассылки | Глобальная остановка сохраняется; /start_service и отдельный пароль |
| OOM Chromium | BROWSER_ENABLED=false и seed URLs; unit ограничивает память 1800 MB |

Обновление: остановите сервис, сохраните data/.env, получите новый код, выполните install.sh и smoke, включите сервис. Версии зафиксированы в requirements*.txt. CI настроен на Python 3.12/Ubuntu 24.04. Фактическое развёртывание на VPS в локальной Windows-сессии не выполнялось.

## Проверки разработчика

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pip install --no-deps --no-build-isolation -e .
.venv/bin/python -m ruff check .
.venv/bin/python -m ruff format --check .
.venv/bin/python -m pytest -q
.venv/bin/python scripts/check_imports.py
.venv/bin/python -m app.main --smoke
bash -n install.sh
```

Smoke создаёт временную БД, fake provider и fake Telegram, выполняет два scan, measured growth, TOP-3, mock-delivery и cleanup. Секреты/сеть не нужны. Fake MP4 никогда не отправляется в настоящий Telegram. Тесты проверяют ranking, фильтры, TTL, approval, auth/команды, состояние после restart, scheduler, media, ошибки, публичный parser и реальные HTTP payload Telegram. Live Telegram delivery требует вашего токена и авторизации: она не заявляется проверенной без них.

## Структура и замена provider

```text
app/config.py          .env, validation, базовые запросы и веса
app/models.py          Video/Metrics/Source и Protocol-интерфейсы
app/providers/         public TikTok и offline fake
app/db.py              SQLite schema и атомарные операции
app/ranking.py         фильтры, язык, velocity, Trend Score
app/source.py          caption/subtitles/OCR и optional TMDB
app/services.py        scan, review, TOP, delivery
app/telegram.py        HTTP transport и fake messenger
app/bot.py             команды, auth, callbacks, polling
app/scheduler.py       timezone-aware jobs
app/cleanup.py         retention и orphan cleanup
app/main.py            запуск, shutdown, smoke
scripts/               provider probe, проверка импорта
systemd/               шаблон unit
tests/                 offline автоматические проверки
```

Для нового источника реализуйте TikTokProvider.search(query,limit), metadata(url), download(video,destination), close(). Верните нормализованный Video с настоящими UTC timestamp и счётчиками, неизвестные followers=None. ID должен быть стабильным и безопасным. Optional begin_scan/end_scan освобождают ресурсы, get_subtitles читает публичные субтитры только для TOP. Подключите экземпляр в app/main.py: ranking/SQLite/Telegram менять не требуется. SourceIdentifier возвращает evidence/confidence; без доказательств title=None.

## Полное удаление

```bash
sudo systemctl disable --now movie-trend-bot
sudo rm -- /etc/systemd/system/movie-trend-bot.service
sudo systemctl daemon-reload
```

При необходимости сохраните data/.env. Затем удалите **проверенный каталог своего clone** вместе с data, media, logs, .venv, .tools и .env через файловый менеджер или `rm -rf -- /точный/путь/movie-trend-bot`. Не удаляйте глобальные Python/FFmpeg/Tesseract packages, используемые другими приложениями. Отзовите токен у BotFather при окончательном отказе от бота.
